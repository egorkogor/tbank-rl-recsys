# RL-дообучение последовательного рекомендателя: GPT-2 + модель вознаграждения на Yambda

Тестовое задание Т-Банка № 2. Базовая модель next item на GPT-2, модель вознаграждения (RM) и RL-дообучение против неё. Главный вопрос — становятся ли рекомендации лучше или модель учится угождать RM.

> Статус: в работе. Разделы результатов заполняются по мере прогонов. Числа OOT появятся один раз, после заморозки.

## 1. Постановка

**Продуктовая рамка.** «Моя волна» Яндекс Музыки: сервис сам ставит следующий трек, пользователь дослушивает его или пропускает.

**Три модели:**
- **Политика π_θ(a | s)** — GPT-2 по истории прослушиваний (токены — идентификаторы треков) выдаёт распределение по 100 тыс. треков.
- **RM r(s, a)** — по той же истории и треку-кандидату предсказывает отклик: долю дослушивания, Listen+ (≥ 50%), пропуск (< 10%), лайк за 24 ч, продолжение сессии (следующий трек в течение 30 минут).
- **RL** максимизирует E[Σ_t r(s ⊕ a_<t, a_t)] − β · Σ_t KL(π_θ ‖ π_ref) при T = 1 (следующий трек) и T = 5 (последовательность; сгенерированный трек дописывается в контекст).

**Контроль без обучения.** При T = 1 у этой задачи есть точное решение: π\*_β(a | s) ∝ π_ref(a | s) · exp(r(s, a) / β). Мы считаем его на топ-1000 исходной модели и сравниваем RL с ним при том же β. Оценка преимущества в RL несмещённая (RLOO, без деления на std), поэтому стационарная точка RL при T = 1 — именно π\*_β, и сравнение корректно.

## 2. Данные

[Yambda-50M](https://huggingface.co/datasets/yandex/yambda):
- 9 238 пользователей, 46,5 млн прослушиваний, 301 день;
- у прослушивания есть `played_ratio_pct`, длина трека, флаг органики; лайки — отдельные события.

**Почему Yambda.** Награду можно собрать из нескольких откликов, а ловушка из условия видна прямо в данных (алгоритмические прослушивания):

| Длина трека | Доля дослушивания | Listen+ | Секунд прослушано |
|---|---|---|---|
| ≤ 90 с | 0,79 | 0,78 | 59 |
| 150–200 с | 0,71 | 0,69 | 127 |
| 250–330 с | 0,66 | 0,64 | 184 |
| > 480 с | 0,56 | 0,54 | 407 |

Награда «доля дослушивания» тянет к коротким трекам, награда «секунды» — к длинным.

**Словарь** — 100 тыс. самых частых треков до дня 287. Покрытие: 89,6% прослушиваний обучения, 85,2% Listen+ в val; это потолок Recall, общий для всех моделей.

## 3. Разбиение и защита от утечек

| Часть | Дни | Зачем |
|---|---|---|
| Обучение | 0–286 | SFT, RM, словарь, статистики треков |
| Состояния RL | снимки на начало дней 273–286 | только контексты, метки не используются |
| val | 287–293 | весь выбор: эпохи, β, награды, контрольные точки |
| OOT | 294–300 | один прогон замороженных моделей |

- **Снимок на начало дня:** контекст пользователь-дня d — только прослушивания до начала дня d, как в Global Temporal Split статьи Yambda.
- **Метки RM с горизонтом** (лайк за 24 ч, продолжение за 30 минут) берутся только у событий, чей горизонт закрывается до дня 287.
- **OOT без переобучения:** разрыв обучение → оценка там 8–14 дней против 1–7 на val. Условие одинаково для всех моделей.
- **Тесты** (`tests/test_no_leakage.py`, 6 штук):
  - контекст строго до дня;
  - выход политики не меняется, если перемешать будущие события;
  - словарь — только по дням обучения;
  - горизонт меток RM закрыт до отсечки;
  - признаки RM при применении совпадают с признаками при обучении;
  - цели дня — ровно Listen+ этого дня.
- **OOT — один раз:** скрипты не запускаются на OOT без `artifacts/freeze.json`.

## 4. Модели

- **SFT (политика).** GPT-2: 4 слоя, d = 256, 4 головы, окно 256 событий.
  - Вход позиции — сумма эмбеддингов трека, исхода (пропуск / частично / Listen+ / неизвестно), органики и интервала до прошлого события. Подаётся через `inputs_embeds`; выходная голова связана с эмбеддингом трека.
  - В 10% позиций исход заменяется на «неизвестно», чтобы модель умела читать сгенерированные треки.
  - Кросс-энтропия по всему словарю, по кускам с пересчётом в обратном проходе; 2 эпохи.
- **RM.** Тот же бэкбон, инициализирован весами SFT. Голова — MLP([h, e, h ⊙ e, side]).
  - side: длина трека, популярность, сколько раз пользователь слушал трек и артиста.
  - Обучение на алгоритмических прослушиваниях; в 30% позиций исход скрыт.
  - Ансамбль из 4 членов на разных 80% пользователей: **m0 учит политику, m1–m3 — «судьи»**, которых политика не видит.
- **RL.** REINFORCE с групповым бейзлайном: G = 8 сэмплов на состояние, преимущество — leave-one-out (RLOO). KL к π_ref считается точно по всему словарю. Один шаг на батч свежих сэмплов, строго on-policy.

## 6. Протокол оценки

**Релевантность** — пользователь-день val, контекст до начала дня, top-100.
- Цель — треки, дослушанные в этот день до ≥ 50%.
- Метрики: Recall@10/100 и NDCG@10/100, а также срез `_new` — только треки, новые для пользователя.

**Вознаграждение** — средний балл top-10 по m0 (`r_train`) и по судьям (`r_judge`). Разрыв между ними — мера взлома RM.

**Поведение:**
- coverage@10;
- доля пользователь-дней с самым частым треком в top-10;
- Жаккар top-10 между пользователями;
- длина трека;
- доля повторов и новых артистов.

**Статистика** — парный бутстрэп по пользователям. Решающие слова те же, что в задании 1, пороги зафиксированы до OOT:
- «лучше» — нижняя граница 95% CI > 0;
- «хуже» — верхняя граница < 0;
- «сопоставимо» — CI содержит 0 и |Δ| < 2% от базы (релевантность) или < 0,005 (награда);
- иначе — «не определено».

## 11. Как воспроизвести

```bash
python -m uv sync                          # Python 3.12, torch 2.12 cu126, transformers 5.9
# events.parquet / items.parquet — из подготовки Yambda-50M (TBANK_DATA указывает на папку)
python scripts/prepare.py                  # artifacts/seq: последовательности, словарь, пользователь-дни
python -m pytest -p no:cacheprovider tests # тесты утечек
cd scripts
python train_sft.py --epochs 2
for m in 0 1 2 3; do python train_rm.py --member $m; done
python eval_rm.py --stage val
python eval_policy.py sft mostpop personal pistar:lp:0.1
python train_rl.py --reward lp --beta 0.1
python eval_policy.py rl:lp_b0.1_T1:400
python eval_multistep.py sft rl:lp_b0.1_T1:400
python compare.py --kind lp
```

Процессы ограничены 3 потоками на логических ядрах 0–2 (`src/rlrec/__init__.py`).
