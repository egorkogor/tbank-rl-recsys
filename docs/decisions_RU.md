# Решения и почему (журнал, 24–25.10.2026)

Черновик раздела README «Решения и почему». Факты и мотивы зафиксированы по ходу работы; формулировки владелец перепишет своими словами.

| № | Решение | Почему | Что получилось |
|---|---|---|---|
| 1 | Yambda-50M, а не KION; X5 не брать | В Yambda есть доля дослушивания, длина трека, лайки и органика. Ловушка «короткие / длинные треки» видна прямо в данных. В KION оставлена только последняя запись пары «пользователь × фильм», поэтому механизм повторов не перенести. В X5 нет отклика на показ | Разбиение совпадает с заданием 1, отчёты сверяются |
| 2 | Релевантность — множество треков, дослушанных за день, а не следующее событие | Next item на логе клонирует смесь пользователя и прода, а дневное множество ближе к «понравилось» | Повторы стали главным фактором метрики (решение 3) |
| 3 | Канал повторов в политике | Голая GPT-2 в 5 раз хуже «повтори любимое». Без канала RL просто перенёс бы знание о повторах из RM в политику, и рост выглядел бы как успех RL | NDCG@10: 0,035 → 0,173; литература (Abbattista et al.) показывает ту же картину |
| 4 | Ансамбль RM: обучающая + судьи; затем судьи на снимке начала дня | Обучающая RM не может быть судьёй самой себе. Судьи m1–m3 оказались копиями (разброс 0,011), и RM на снимке начала дня самоуверенна | Судьи m4–m6 откалиброваны и в 5 раз независимее. Но и они ошибаются вместе с m0 при взломе — отсюда внешний судья |
| 5 | Бустинг задания 1 как внешний судья | Другое семейство моделей, обучено на реальных показах | Раздел 7.6 README |
| 6 | RLOO без деления на std, точный KL | Тогда стационарная точка RL при T = 1 — ровно π\*_β, и RL можно сравнить с закрытой формой при том же β | При T = 1 π\* лучше RL (раздел 7.4) |
| 7 | Закрытая форма π\* как эталон | Если RL не лучше переранжирования, RL при T = 1 не нужен | Выбранная точка — π\*, а не RL |
| 8 | Плацебо-награда | Отделить эффект «RL + KL» от смысла награды | Плацебо при β = 0,02 — 68 треков на всех; сила сдвига задаётся разбросом награды |
| 9 | Главная метрика — минуты в неделю → сбалансированные минуты B (владелец) | Голые минуты не держат баланс старого и нового; формула с «костами» сокращается тождественно | B = T · K(s): ≤ T, равенство при целевой доле нового, читается в минутах, растёт без потолка |
| 10 | В B только «старое / новое», без артистов; избыток нового штрафовать мягче (владелец) | У любимых артистов может не быть новинок; бонус за новых артистов делает из всех «меломанов» — это показала награда `disc` | 50/50 — штраф −1,3% вместо −5,2% |
| 11 | Возвраты — сессии, а не активные дни (владелец) | Сессии важнее | Для +2% нужно 12 тыс. пользователей на группу против 34 тыс. для B |
| 12 | Дослушивание — защитная метрика, а не слагаемое (владелец + данные) | Бонус «минуты + дослушивание» уравновешивает длину только при ~25 минутах за дослушанный трек: это курс на лезвии ножа | `mlp` схлопнулся в 10-минутные треки; дослушивание стало пятым ограничением правила |
| 13 | Награды в минутах — своя шкала β | Разброс минут между треками в ~10 раз больше, чем у вероятностей | «Минуты» при β = 0,5 → 14-минутные треки; при β = 5 — спокойно |
| 14 | Формулы из литературы (WTG, линейная полезность) проверить, а не принять на веру | Их создавали для предсказателя, а не как награду под давлением оптимизатора | WTG при β = 0,1 → 22-минутные треки: в RL поправка на длительность становится взломом |
| 15 | Порядковая награда как в ARGUS (Яндекс) | Публичный рецепт Яндекса: «пропуск < дослушал < лайк», попарно на соседних показах; длину решать переранжированием (хендбук ШАД) | `mix` при β = 0,5 держит точность; π\* `mix` даёт NDCG +2,3% |
| 16 | Правило выбора и гипотезы зафиксировать до полной оценки и OOT | Иначе выбор подгоняется под результат | 23 из 69 прошли ограничения; поправки владельца помечены временем |
| 17 | OOT один раз, без переобучения | Честная проверка на неделе, не участвовавшей ни в одном решении | Раздел 8 README |
| 18 | Один GPU-процесс за раз, потолок VRAM, чекпойнты и автоперезапуск | 16 ГБ ОЗУ на двоих с заданием 1 и Minecraft. Драйвер сбрасывал память GPU в ОЗУ (замедление в 6 раз), падения по CUDA OOM | Ни одного потерянного результата после первых 33 минут |
